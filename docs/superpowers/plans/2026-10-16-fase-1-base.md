# Fase 1: Base & Infraestrutura — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Configurar a fundação técnica completa do sistema Evolução Argolas com Next.js, Firebase (Auth + Firestore offline), design system de alto contraste (WCAG 2.2 AA) e navegação inicial por perfis.

**Architecture:** Aplicação Next.js (App Router) com TypeScript e Tailwind CSS conectada ao Firebase SDK com persistência offline ativa no navegador. A camada de regras de negócio é isolada em módulos puros testados via Vitest, com controle de acesso e telas iniciais guiadas por perfil (Produção, Logística, Gestão).

**Tech Stack:** Next.js 14/15, React 18/19, TypeScript, Tailwind CSS, Firebase SDK v10 (Auth & Firestore offline), Vitest.

**Spec:** [docs/superpowers/specs/2026-10-16-evolucao-argolas-gestao-design.md](file:///c:/Users/Pedro%20o%20Rich/Desktop/projects%20vibecoding/gestao%20ev.%20argolas/docs/superpowers/specs/2026-10-16-evolucao-argolas-gestao-design.md)

## Global Constraints

- Valores monetários são sempre manipulados e armazenados em centavos inteiros (integers), nunca em ponto flutuante.
- Paleta de cores estrita: Preto `#111111`, Laranja `#FF7A00`, Azul `#1565C0`, Branco `#FFFFFF`, Fundo `#F5F5F7`.
- Botões de ação com altura mínima de 48px e texto de corpo com no mínimo 18px (acessibilidade para pessoas +50).
- Nenhum dado é excluído fisicamente (soft delete com flag `ativo: false` e registro em auditoria).
- Fuso horário fixo em `America/Sao_Paulo`.
- Textos em linguagem do dia a dia em português do Brasil, sem jargões técnicos.
- Suporte a modo offline obrigatório com indicação visual de conectividade.

## Review Focus

1. Tentativa de calcular dinheiro usando float ou divisão sem arredondamento inteiro: o sistema deve sempre garantir centavos inteiros truncados/arredondados confiavelmente.
2. Acesso a tela de outro perfil via URL direta: o guard de rota deve redirecionar para a home do perfil correto do usuário logado.
3. Queda de conexão no meio da operação: a aplicação deve continuar responsiva e salvar no cache local do Firestore com status offline visível.
4. Tamanho de toque inferior a 48px em telas móveis: componentes de botão devem rejeitar tamanhos menores que `min-h-[48px]`.
5. Erro no login ou tentativa indevida: mensagem deve ser amigável e compreensível em português claro ("E-mail ou senha incorretos"), sem detalhes técnicos de API.
